# Humaicraft Foundation v0.1.0 — The First Seed

## Summary

v0.1.0 establishes the first reviewable version of the Humaicraft Foundation and the minimum repository governance needed for careful participation.

This release is intentionally small. It does not attempt to define every standard or implementation. It creates a durable starting point that future Humaicraft projects can adopt, test, question, and improve.

## What this release establishes

- a shared Vision and Mission;
- Values and Principles for making trade-offs;
- a public Manifesto;
- a Charter defining durable commitments, boundaries, and human authority;
- a Glossary for recurring terms;
- contribution and conduct expectations;
- review-oriented Pull Request and Issue templates;
- a roadmap for standards, templates, governance, and product adoption.

## Core commitments

Humaicraft prioritizes:

1. people and data safety;
2. correctness and reliability;
3. clarity and maintainability;
4. accessibility and inclusion;
5. reproducibility and operability;
6. performance;
7. development speed;
8. implementation convenience.

Humans retain judgment, responsibility, and final authority. AI may support exploration, implementation, verification, review, and documentation, but it does not replace accountability.

## Validation performed

- reviewed the hierarchy and purpose of the Foundation documents;
- checked recurring terminology across the English and Japanese content;
- checked repository-relative links introduced by the release;
- reviewed public templates for accidental solicitation of secrets, personal information, private evidence, or sensitive vulnerability details;
- confirmed that the release adds no executable code, runtime dependency, credential, or external integration.

## Security and privacy

Public Issues and Pull Requests must not contain credentials, personal information, private evidence, or sensitive vulnerability details.

A dedicated private reporting destination is still required before public release. This is tracked in Issue #5 and remains a release blocker.

## Accessibility

The documents use semantic Markdown headings, descriptive link text, explicit instructions, and do not depend on color or imagery to communicate meaning. English and Japanese sections should continue to be reviewed for equivalent intent rather than literal translation alone.

## License proposal

The repository content is proposed to use Creative Commons Attribution 4.0 International (`CC-BY-4.0`). The choice permits reuse and adaptation with attribution while keeping the Foundation broadly usable.

This license choice requires final human approval before v0.1.0 is released or the repository is made public.

## Known limitations

- detailed coding, security, accessibility, review, documentation, and release standards are future phases;
- reusable repository and product templates are not part of this release;
- Foundation Decision Records and a maintainer handbook are not yet defined;
- the private reporting process is not yet operational;
- adoption by individual Humaicraft products has not yet been validated.

## Adoption and migration

No automated migration is required. Projects adopting this release should:

1. reference the Foundation version they follow;
2. identify any local exceptions or stronger requirements;
3. avoid claiming full compliance without a review;
4. preserve human approval for consequential decisions;
5. record improvement proposals as focused Issues.

## Rollback

Before public release, revert the v0.1.0 preparation commits or close the Pull Request without merging.

After publication, do not silently rewrite the release history. Publish a corrective patch release, explain the change in the changelog, and preserve the original tag unless a security or legal reason requires a different response.

## Next phase

After v0.1.0, the recommended next deliverable is the Humaicraft Growth Board, followed by a reusable repository template. Ideas that are useful but not required for the current release should be preserved as Issues rather than expanding the release scope.
